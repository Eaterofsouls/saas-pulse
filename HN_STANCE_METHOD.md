# Hacker News Stance Classification Methodology

This document details how developer sentiment towards building internal tools versus buying commercial SaaS was extracted and measured for **SaaS-Pulse**.

> **CORRECTION (2026-10-31):** A prior version of this document implied human verification of the 60 test stances. No human verified any stance label. All 60 gold labels are keyword-rule generated. The "44% build / 36% buy" corpus-level claim appearing on slide 9 of run 20261030_0023 had no source in any output file; it has been removed.

---

## 1. Corpus Scope & Pacing
- **Source**: Hacker News via Algolia REST API (`hn.algolia.com/api/v1/search_by_date`).
- **Temporal Coverage**: 2023-01-01 to 2026-10-28.
- **Search Query Seeds**:
  - `"internal tools AI"`
  - `"replace Salesforce with"`
  - `"vibe coded internal tool"`
  - `"build vs buy AI"`
  - Mentions of popular low-code / internal tooling stacks: Appsmith, Budibase, Retool, Supabase.
- **Total Deduplicated Records**: 7,829 comments/stories (≥ 80 characters).
- **Privacy Protocol**: Author usernames pseudonymized using SHA-256 (`author_hash = sha256(username)`).

---

## 2. Stance Taxonomy Definitions
Each comment is evaluated against three mutually exclusive stances:
1. `build_internal`: The author advocates, reports, or plans the replacement of a commercial SaaS product with a custom in-house build, an LLM-assisted tool ("vibe coding"), or an open-source low-code framework.
2. `buy_saas`: The author argues against in-house builds, citing maintenance debt, non-core distractions, regulatory compliance, billing/tax complexity, or vendor security guarantees.
3. `hybrid_or_neutral`: The author presents a nuanced trade-off analysis, recommends selective hybrid adoption, or poses questions without taking a firm side.

---

## 3. Gold Benchmark Label Generation

**No LLM was used.** The 60 gold stance labels were generated by the keyword rules in Section 2 above:

- A comment is assigned `build_internal` if any of these substrings appear (case-insensitive): `built internal`, `built our own`, `vibe coding`, `vibe coded`, `replaced salesforce`, `cancelled our subscription`, `replace salesforce`, `cancel subscription`.
- A comment is assigned `buy_saas` if any of these substrings appear: `buy saas`, `off the shelf`, `reinvent the wheel`, `not worth building`, `maintenance overhead`, `not our core`, `stick with`.
- Otherwise the comment is assigned `hybrid_or_neutral`.

The column `user_corrected_label` is a **direct copy** of `predicted_stance`. The two columns are identical in 60/60 rows (100%). Only 3 distinct rationales exist (one per class, verbatim repeated).

**No human reviewed any stance row.** This is a key limitation.

---

## 4. Gold Benchmark Dataset

- **Sample Size**: N=60 comments.
- **Stratification**: Exactly 20 `build_internal`, 20 `buy_saas`, 20 `hybrid_or_neutral`.
- **Split**: All 60 rows are test-only (no HN training).
- **Selection**: After applying keyword rules to 7,829 comments, rows were selected with `seed=42` to balance classes at 20 each.

---

## 5. Evaluation Method (v2 Notebook)

All methods use **constrained log-probability scoring** — no free-text JSON parsing:

```python
LABELS = ["build_internal", "buy_saas", "hybrid_or_neutral"]

def score_labels(model, tokenizer, prompt, candidates):
    """Returns dict {label: log_prob}."""
    prompt_ids = tokenizer(prompt, return_tensors="pt").to(model.device)
    scores = {}
    for label in candidates:
        label_ids = tokenizer(label, return_tensors="pt",
                              add_special_tokens=False).input_ids.to(model.device)
        full_ids = torch.cat([prompt_ids.input_ids, label_ids], dim=1)
        full_labels = torch.cat([
            torch.full_like(prompt_ids.input_ids, -100),
            label_ids
        ], dim=1)
        with torch.no_grad():
            loss = model(input_ids=full_ids, labels=full_labels).loss
        scores[label] = -loss.item() * label_ids.shape[1]
    return scores
```

- **Sanity gate**: If any method assigns >70% of 60 predictions to one class, it is flagged as a pipeline bug and not reported as a result.
- **Few-shot exemplars**: 6 comments (2 per class) selected from the 7,829-comment pool excluding the 60 test IDs, using `seed=42`. Exemplar IDs are logged in `metrics.json`.
- **Optional corpus-level inference**: If time permits, the best-performing method is run on a random 1,500-comment sample (seed=42) to estimate corpus-level stance shares, reported with bootstrap 95% CI. If this step is skipped, no corpus-level percentages appear on slides.
